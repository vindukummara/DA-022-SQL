DAY 1 — MYSQL BASICS
-------------------------
1. DATA
--------

-Data is generally unprocessed and may not have meaningful information by itself.
>Example:
101

23

3. FILE MANAGEMENT SYSTEM (FMS)
---------------------------------------
-A File Management System is used to store and manage data in files.

Key functions of FMS:
--------------------
1.Create a file
2.Open a file
3.Read a file
4.Update a file
5.Delete a file
6.Share data
7.Provide access to data

Drawbacks of FMS:
------------------------
1.Data inconsistency — same data may have different values in different files.
2.Less security — difficult to control data access.
3.Data redundancy — duplicate data may be stored.
4.Backup and recovery problems — recovering data can be difficult.
5.Data manipulation problems — managing large amounts of data is difficult.
-These problems led to the development and use of databases and DBMS.

4. DATABASE
-------------------
-A database is an organized collection of data used to store and manage information.
-Example:

DAY 2 — DATA MODELS, SQL & DATA TYPES
-----------------------------------------
1. DATA MODEL
---------------
A data model is a way of organizing and representing data. It defines how data is stored, related, and manipulated in a database.

Types of Data Models:
--------------------------
1. Hierarchical Data Model
-------------------------------
.Data is organized in a tree-like structure.
.It contains parent-child relationships.
.Each child can have only one parent.
.One parent can have multiple children.
.It is easy to retrieve and maintain simple hierarchical data.
.It is not suitable for complex relationships.
-Example:
-----------
Institute
   |
   +--- Course
          |
          +--- Student 1
          +--- Student 2


2. Network Data Model:
--------------------------
.Data is organized using nodes and relationships.
.One parent can have many children.
.One child can have multiple parents.
.It is more flexible than the hierarchical model.
.It is suitable for many-to-many relationships.
-Example:
Student 1 ---- Course 1
    |             |
    |             |
    +----------- Course 2
Student 2 ---- Course 1
-For example:
.One student can take multiple courses.
.One course can have multiple students.

3. Object-Oriented Data Model
-----------------------------
.Data is represented as objects.
.Objects contain:
   -Properties → characteristics/data
   -Behaviors → actions/functions
Example:
Student Object

Properties:
student_id
student_name
course

Behaviors:
study()
attend_class()

4. Relational Data Model
-Data is stored in tables.
-Tables contain rows and columns.
-A column represents a field/attribute.
-A row represents a record.
Example:
sid	sname	course
101	Rahul	DA
102	Sita	Python

2. DATA MODEL LEVELS
----------------------------
There are three levels of data abstraction:
1. Conceptual Level
---------------------------
-Describes the overall structure of the database.
-Example:
Student → Course → Department

2. Logical Level
---------------------------------
-Describes tables, columns, relationships, keys, etc.
Example:
-Student(student_id, student_name, course_id)
3. Physical Level
-----------------------
-Describes how data is actually stored in the storage system.

DAY 3 — CONSTRAINTS & DDL COMMANDS:
--------------------------------------------
1. CONSTRAINTS
------------------
-Constraints are rules applied to table columns to maintain:
.Data consistency
.Data integrity
.Data accuracy
Types of Constraints:
-------------------
1.UNIQUE
2.NOT NULL
3.PRIMARY KEY
4.FOREIGN KEY
5.CHECK
6.DEFAULT

2. UNIQUE
---------------
-The UNIQUE constraint ensures that duplicate values are not allowed in a column.
-Example:
CREATE TABLE student
(
    student_id INT UNIQUE,
    name VARCHAR(20)
);
Here, every student_id must be different.

3. NOT NULL
------------
-The NOT NULL constraint ensures that a column cannot contain NULL values.

Example:
CREATE TABLE student
(
    student_id INT,
    name VARCHAR(20) NOT NULL
);

The name column must have a value.


4. PRIMARY KEY
--------------------------
-A PRIMARY KEY uniquely identifies each row in a table.
-A primary key has two important properties:
.UNIQUE
.NOT NULL
Example:
CREATE TABLE student
(
    student_id INT PRIMARY KEY,
    name VARCHAR(20)
);

Each student_id must be unique and cannot be NULL.

Example: Student ID, Employee ID, Customer ID.

5. FOREIGN KEY
-------------------
-A FOREIGN KEY is used to establish and maintain a relationship between two tables.
-The foreign key usually references a primary key or unique key in another table.
Example
-------
CREATE TABLE employee
(
    id INT PRIMARY KEY,
    name VARCHAR(20)
);

Another table:
-------------
CREATE TABLE department
(
    did INT,
    dname VARCHAR(20),
    FOREIGN KEY (did) REFERENCES employee(id)
);
Here:
employee.id
     ↑
     |
department.did

-The department.did column references employee.id.
6. CHECK
--------------
-The CHECK constraint ensures that values satisfy a specified condition.

Example:
------
CREATE TABLE student
(
    id INT,
    name VARCHAR(20),
    age INT CHECK (age > 0 AND age < 120)
);

Valid:
25
50
100
Invalid:
-5
0
125
7. DEFAULT
----------
-The DEFAULT constraint automatically provides a value when no value is supplied during insertion.
Example:
---------
CREATE TABLE employee
(
    id INT,
    name VARCHAR(20),
    address VARCHAR(20) DEFAULT 'HYD'
);

If you insert:

INSERT INTO employee(id, name)
VALUES (101, 'Rahul');
The address automatically becomes:
-HYD

DAY 5 — MySQL
--------------
1. CREATE A NEW TABLE FROM AN EXISTING TABLE
-To create a new table with the same structure as an existing table:
CREATE TABLE new_table LIKE old_table;
CREATE TABLE employee LIKE emp;
This copies the table structure, but not the data.

2. COPY ALL DATA FROM ONE TABLE TO ANOTHER
-----------------------------------------------------------
-To copy all records from an existing table:
INSERT INTO new_table
SELECT * FROM old_table;
Example:
INSERT INTO employee
SELECT * FROM emp;
This copies all rows from emp into employee.

Structure + Data together
-----------------------------
CREATE TABLE employee LIKE emp;
INSERT INTO employee
SELECT * FROM emp;

3. AUTO_INCREMENT
---------------------------
AUTO_INCREMENT is a MySQL feature that automatically generates a unique numeric value when a new row is inserted.
It is commonly used with a PRIMARY KEY.

CREATE TABLE student
(
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(20),
    age INT
);

INSERT INTO student(name, age)
VALUES
('Sam', 25),
('Ram', 30),
('Geetha', 60);
The id is generated automatically.

# 2. SET OPERATORS
-------------------------
Set operators are used to **combine the results of two or more `SELECT` queries**.

### Types of Set Operators
---------------------------
1. `UNION`
2. `UNION ALL`
3. `INTERSECT`
4. `EXCEPT`

### Important condition

The `SELECT` queries should have:

* The same number of columns
* Corresponding columns with compatible data types

---

1.UNION
---------------------
-Combines results and **removes duplicate rows**.

SELECT name FROM student1
UNION
SELECT name FROM student2;
```

2.UNION ALL
------------
-Combines results and **keeps duplicates**.

```sql
SELECT name FROM student1
UNION ALL
SELECT name FROM student2;
```

3.INTERSECT
------------
-Returns rows that are **common in both queries**.

```sql
SELECT name FROM student1
INTERSECT
SELECT name FROM student2;
```

4.EXCEPT
------------
-Returns rows present in the **first query but not in the second query**.

SELECT name FROM student1
EXCEPT
SELECT name FROM student2;

##JOINS
-------------
A **JOIN** is used to combine rows from **two or more tables** based on a related/common column.

Example:
SELECT *
FROM employee e
JOIN department d
ON e.dept_id = d.dept_id;
The common column here is `dept_id`.

## Types of JOINs
====================
1. CORE JOINS
2.OUTER JOINS

1.Core Joins
-------------------
1. **INNER JOIN**
2. **NATURAL JOIN**
3. **EQUI JOIN**
4. **NON-EQUI JOIN**

**1. INNER JOIN**
--------------------
INNER JOIN returns only the ROWS that have matching values in both tables.

SELECT *
FROM employee e
INNER JOIN department d
ON e.dept_id = d.dept_id;
```

**2. NATURAL JOIN**
---------------------------
NATURAL JOIN automatically joins two tables using columns that have the **same name and compatible data type**.

SELECT *
FROM employee
NATURAL JOIN department;


**3. EQUI JOIN**
----------------------
EQUI JOIN combines tables using an **equal (`=`) condition** between columns.

SELECT *
FROM employee e
JOIN department d
ON e.dept_id = d.dept_id;
```

**4. NON-EQUI JOIN**
-------------------
NON-EQUI JOIN combines tables using operators other than `=` such as `>`, `<`, `>=`, `<=`, or `BETWEEN`.

SELECT *
FROM employee e
JOIN salary_grade s
ON e.salary BETWEEN s.min_salary AND s.max_salary;
```

Easy to Remember

* **INNER JOIN** → Only matching records
* **NATURAL JOIN** → Automatically joins same-named columns
* **EQUI JOIN** → Join using `=`
* **NON-EQUI JOIN** → Join using `>`, `<`, `BETWEEN`, etc.

2.Outer Joins
-----------------------------
1. **LEFT JOIN / LEFT OUTER JOIN**
2. **RIGHT JOIN / RIGHT OUTER JOIN**
3. **FULL JOIN / FULL OUTER JOIN**

1.LEFT JOIN
----------------------
Returns **all rows from the left table** and matching rows from the right table.

```sql
SELECT *
FROM employee e
LEFT JOIN department d
ON e.dept_id = d.dept_id;
```

2.RIGHT JOIN
----------------
Returns **all rows from the right table** and matching rows from the left table.

```sql
SELECT *
FROM employee e
RIGHT JOIN department d
ON e.dept_id = d.dept_id;
```

3.FULL JOIN
--------------------
Returns **all rows from both tables**, matching where possible.

SELECT *
FROM employee e
FULL OUTER JOIN department d
ON e.dept_id = d.dept_id;
```

**MySQL note:** MySQL does not directly support `FULL OUTER JOIN`; it can be simulated using `UNION` of `LEFT JOIN` and `RIGHT JOIN`.

A **subquery** is a query written **inside another query**.

* A subquery is usually enclosed in **parentheses `()`**.
* The inner query executes as part of the outer query.

);

4. Correlated Subquery
----------------------------
What is a correlated subquery?

A **correlated subquery** is a subquery that depends on the **current row of the outer query**.
The inner query runs repeatedly for each row of the outer query.

### Example 1: Employees earning more than their department average

```sql
SELECT e.emp_name, e.salary, e.dept_id
FROM employee e
WHERE e.salary > (
    SELECT AVG(e1.salary)
    FROM employee e1
    WHERE e1.dept_id = e.dept_id
);
```

### How it works

For every employee:

1. Take the employee's `dept_id`.
2. Find the average salary of that department.
3. Compare the employee's salary with that average.
4. If salary is greater → display the employee.

## 1. What is a View?

A **View** is a **virtual table (logical table)** based on the result of a `SELECT` query.

* A view generally **does not store the actual data separately**.
* It stores the **SQL query definition**.
* When we query the view, the database retrieves the data from the underlying table(s).

### Syntax

```sql
CREATE VIEW view_name AS
SELECT column1, column2
FROM table_name;
```
ex:
CREATE VIEW employee_view AS
SELECT emp_id, emp_name, salary
FROM employees;

Now we can use:
SELECT * FROM employee_view;

# 2. Advantages of Views
---------------------------
1. Security
--------------
Views can hide sensitive columns from users.

CREATE VIEW employee_public AS
SELECT emp_id, emp_name, department
FROM employees;

Here, we don't expose salary.

2. Avoid unnecessary columns

We can show only the required columns instead of the entire table.

3. Simplify complex queries

A complicated query can be stored as a view and reused.

4. Improve readability

Instead of repeatedly writing a long query, we can simply use the view name.

# 3. Types of Views
---------------------------
There are two commonly discussed types:

1.Simple View
------------
A **simple view** is created from **one table** and generally does not contain complex operations such as:

* Joins
* Aggregate functions
* `GROUP BY`
* `HAVING`

Example:

```sql
CREATE VIEW employee_view AS
SELECT emp_id, emp_name, salary
FROM employees;

2. Complex View
------------------
A **complex view** is created using **multiple tables** or contains complex operations such as:

* Joins
* Aggregate functions
* `GROUP BY`
* `HAVING`

Example:
CREATE VIEW department_salary AS
SELECT d.department_name, AVG(e.salary) AS avg_salary
FROM employees e
JOIN departments d
ON e.department_id = d.department_id
GROUP BY d.department_name;

# 4. How to Check View Structure?

In MySQL:
DESC view_name;

Example:

DESC employee_view;

You can also use:

```sql
SHOW CREATE VIEW employee_view;

This shows the SQL query used to create the view.
# 5. Can We Update a View?

**Yes, some views can be updated.**

A simple view is generally **updatable** if it satisfies the database's rules for updatable views.

Example:

```sql
CREATE VIEW employee_view AS
SELECT emp_id, emp_name, salary
FROM employees;
```

We can potentially update it:

```sql
UPDATE employee_view
SET salary = 50000
WHERE emp_id = 101;
```

The underlying `employees` table will be updated.

### Important interview point

A view containing things like:

* `GROUP BY`
* `HAVING`
* Aggregate functions such as `SUM()`, `AVG()`, `COUNT()`
* Certain `JOIN`/complex query structures
* `DISTINCT`
* `UNION`

may **not be updatable**.

# 6. How to Delete a View?

Use:
DROP VIEW view_name;
```

Example:
DROP VIEW employee_view;
```

**Important:** Dropping a view does **not normally delete the underlying table data**.

Normally, a view stores the query definition rather than storing a separate copy of the underlying data.

Q3. What is the syntax to create a view?

CREATE VIEW view_name AS
SELECT ...
FROM ...;

Q4. What is a simple view?
A view created from one table without complex operations such as joins and aggregate functions.

Q5. What is a complex view?
A view involving multiple tables or complex operations such as joins, aggregate functions, `GROUP BY`, or `HAVING`.

Q6. Can we update a view?
Yes, an updatable view can be updated, and the changes are reflected in the underlying table.

Q7. How do you see the structure of a view?
DESC view_name;

Q8. How do you see the definition of a view?
SHOW CREATE VIEW view_name;

Q9. How do you delete a view?
DROP VIEW view_name;

Q10. Why are views used?
 Mainly for **security, simplifying queries, hiding unnecessary columns, and improving readability/reusability**.
